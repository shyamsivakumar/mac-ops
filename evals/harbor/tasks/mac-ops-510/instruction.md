# MO-1065 · Proof file per PR: every check passed, failed or not run, with commands

## Goal and why
Every PR carries a proof file listing each check as passed, failed or not run, with the command.

## Context
This ticket was filed from the coordinator inbox improvements list, where it is the second mac-ops item. Today the PR body carries a single pass or fail line for the builder check with the head SHA, and the check run itself is transient output; nothing is kept per PR that names each individual check as passed, failed or not run together with the command that ran it. The list asks for that record, so the item sits in the backlog as the first step that produces it.

## Design fit
Generated by the existing builder check step; the gate reads it.

## Scope and non-goals
In: the proof file. Out: new checks.

## Acceptance and proof
One PR shows the file; the gate brief reads it.

## Must not cause
Any permission, guard, sandbox or access change; any change to bot order paths or live services.

## Data/secrets and stop conditions
No secrets. One turn of about 20 minutes; split before starting if larger. Stop and report if it can only be bolted on.

The repository is at `/app`. Make the change there. Do not edit test files.
